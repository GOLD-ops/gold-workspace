# AI 使用与验证记录

开发工具为 Codex，参与需求拆解、界面、前后端实现、数据适配、测试和文档；产品模型为 DeepSeek deepseek-flash。模型仅生成条件 JSON、默认假设、未支持要求，原始财务和行情数据来自金融接口。系统提示词保存在 src/interpreter.js，请求 ID、模型、用量、校验条件可追溯，不包含密钥。

## 首版真实验证

2026-10-10 调用了真实 DeepSeek、扶摇和 iFinD。LIVE-VALIDATION.json 保存脱敏摘要、请求 ID 和用量，授权原文不提交。

- “经营改善、估值合理、走势相对稳定”生成 5 项条件。
- 明确银行、PE≤15、营收同比≥5%时保留阈值和行业限制。
- 扶摇财报、行情、估值及历史请求成功，结果可回到原始字段。
- iFinD 财务原文成功返回；金额口径可能不同，界面显示原文及提醒，不自动认定一致。

## 已修正的错误或不合理结果

1. 旧模型名称不可用：检查实际服务后改用 deepseek-flash，并重新验证。
2. 本地规则误将“走势相对稳定”中的“相对”解释为行业估值：改为分句内匹配，并加入回归测试。
3. AI 可能遗漏明确阈值：加入与确定性提取条件对照，漏掉则回退并说明。
4. 负基期产生误导性同比、亏损产生负 PE：改为未知并注明原因。
5. 扶摇就绪时间被误认为交易日：改用同源最新日 K 线作为研究截止日，明确推导口径。
6. 累计与季度混淆：条件明示累计口径；iFinD 单位差异保留原文，不做未经校验的自动一致结论。
7. 授权数据可能进入公开构建：加入构建拒绝规则、独立私有采集输出和忽略规则。

自由文本理解和合规关键词保护不完备；复杂变体仍需用户检查。全部条件需确认，冲突、缺失与过期不得自动放行。默认阈值是可修改研究假设。

## 2026-10-10 交互简化与复核

用户指出原界面难懂、默认逻辑太复杂；确认以一句话输入作为主入口后，Codex 沿用个人工具站的视觉样式改版。候选人决定取消默认的“利润增速改善”，仅在明确输入或高级编辑中使用。同步修改本地映射、大模型提示词和输出校验；模型擅自添加该指标时回退并解释。指标提供白话、口径和限制三层说明；公式与原始响应折叠。

真实 DeepSeek 复核生成四个默认条件，模式 llm，请求 ID `19df29ab-3587-4feb-9cdd-b9d08ba14f30`。浏览器也完成真实模型草案、用户确认、扶摇刷新、12/11/1 分类、PE 25→15 后 8/15/1 分类、逐项依据、比较与保存。公开快照的复现测试单独核对同一四项策略的数量，实时来源的波动数值可能不同。原始授权字段不提交。

测试发现一处手写预期名单错误：取消增速条件后新增的是美的集团、长江电力和中国石化，逐项检查其增速差均小于0后修正断言。还发现“利润增速提升至少3个百分点”的同义表达未保留数字，补充解析与明确阈值回归测试。旧版五条件调用记录仍保留在 LIVE-VALIDATION.json，不能当作新版默认结果。

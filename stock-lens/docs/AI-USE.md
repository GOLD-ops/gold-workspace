# AI 使用与验证记录

开发工具为 Codex，参与需求拆解、界面、前后端实现、数据适配、测试和文档；产品模型为 DeepSeek deepseek-flash。模型仅生成条件 JSON、默认假设、未支持要求，原始财务和行情数据来自金融接口。系统提示词保存在 src/interpreter.js，请求 ID、模型、用量、校验条件可追溯，不包含密钥。

## 首版真实验证

2026-10-10 调用了真实 DeepSeek、扶摇和 iFinD。LIVE-VALIDATION.json 保存脱敏摘要、请求 ID 和用量，授权原文不提交。

- “经营改善、估值合理、走势相对稳定”生成 5 项条件。
- 明确银行、PE≤15、营收同比≥5%时保留阈值和行业限制。
- 扶摇财报、行情、估值及历史请求成功，结果可回到原始字段。
- iFinD 财务原文成功返回；金额口径可能不同，界面显示原文及提醒，不自动认定一致。

## 已修正的错误或不合理结果

1. 旧模型名称不可用：检查实际服务后改用 deepseek-flash，并重新验证。
2. 本地规则误将“走势相对稳定”中的“相对”解释为行业估值：改为分句内匹配，并加入回归测试。
3. AI 可能遗漏明确阈值：加入与确定性提取条件对照，漏掉则回退并说明。
4. 负基期产生误导性同比、亏损产生负 PE：改为未知并注明原因。
5. 扶摇就绪时间被误认为交易日：改用同源最新日 K 线作为研究截止日，明确推导口径。
6. 累计与季度混淆：条件明示累计口径；iFinD 单位差异保留原文，不做未经校验的自动一致结论。
7. 授权数据可能进入公开构建：加入构建拒绝规则、独立私有采集输出和忽略规则。

自由文本理解和合规关键词保护不完备；复杂变体仍需用户检查。全部条件需确认，冲突、缺失与过期不得自动放行。默认阈值是可修改研究假设。

## 2026-10-10 交互简化与复核

用户指出原界面难懂、默认逻辑太复杂；确认以一句话输入作为主入口后，Codex 沿用个人工具站的视觉样式改版。候选人决定取消默认的“利润增速改善”，仅在明确输入或高级编辑中使用。同步修改本地映射、大模型提示词和输出校验；模型擅自添加该指标时回退并解释。指标提供白话、口径和限制三层说明；公式与原始响应折叠。

真实 DeepSeek 复核生成四个默认条件，模式 llm，请求 ID `19df29ab-3587-4feb-9cdd-b9d08ba14f30`。浏览器也完成真实模型草案、用户确认、扶摇刷新、12/11/1 分类、PE 25→15 后 8/15/1 分类、逐项依据、比较与保存。公开快照的复现测试单独核对同一四项策略的数量，实时来源的波动数值可能不同。原始授权字段不提交。

测试发现一处手写预期名单错误：取消增速条件后新增的是美的集团、长江电力和中国石化，逐项检查其增速差均小于0后修正断言。还发现“利润增速提升至少3个百分点”的同义表达未保留数字，补充解析与明确阈值回归测试。旧版五条件调用记录仍保留在 LIVE-VALIDATION.json，不能当作新版默认结果。


## 2026-10-11 页面层级修正

用户指出前版仍将所有信息堆在一页。Codex将布局改为三个互斥步骤，删除重复统计，缩短辅助文案，并在结果中保留已执行条件摘要。现场验证发现跳转只滚动到main会让工具标题离开屏幕，改为返回页面顶部并将键盘焦点交给当前步骤标题；编辑阈值后继续查看旧结果时，保持旧条件与数量且禁止保存。新增状态门禁回归测试，避免修改原句后跳过重新整理。真实AI仍只负责条件草案，金融引擎和原始数据口径未变。

## 2026-10-11 AI 解析误报修复与真实复核

用户反馈“AI生成了未知字段或非法阈值”。用户未提供触发报错的原句，本轮调查只验证可复现的相关原因，不能认定已复现其原句或找到唯一原因。Codex检查模型输出校验并用少量真实 DeepSeek 请求核对：旧代码把引擎的所有非冲突错误合并为同一个提示，其中包含“至少启用一条条件”。因此，模型在只指定行业、仅提未接入指标时合法返回空 `conditions` 数组，也被误报为未知字段或非法阈值。

| 实际测试输入 | 修复前证据 | 修复后证据 |
| --- | --- | --- |
| 银行行业 | 空条件被误报；请求 ID `8ee3694d-eb4a-4c25-8443-70532815c075` | 模式 llm，保留银行范围，提示补充可执行指标；请求 ID `8dee1bb2-9029-4179-9a48-19e26c087acc` |
| ROE至少10% | 空条件与未接入说明被误报；请求 ID `09a0dc89-3ee5-4429-882f-941f1c1c103c` | 模式 llm，明确 ROE 未接入并提示补充指标；请求 ID `4ed98224-a28e-4d0e-965e-846219d5ba4f` |
| 经营改善、估值合理、走势相对稳定 | 正常四条件；请求 ID `691b42ca-98cd-442e-86a9-8b5d029bf1d6` | 正常四条件，未支持要求为空；请求 ID `5a979722-eb69-4ac5-888d-c97c707c8aea` |

修正后，合法空条件进入澄清状态，筛选引擎仍要求至少一条启用条件。未知字段、非法运算符、越界阈值、结构错误、接口异常分别给出具体诊断；发生回退时保留可取得的请求 ID、诊断代码与校验说明，本地规则结果仍需用户检查。白名单、阈值范围、明确数字和严格比较方式的校验继续执行。

仅对纯数字字符串进行显式类型转换，例如模型把 `15` 输出为 `"15"`；转换记录保存在 `normalizations`，同时写入假设说明，保留指标既定单位及原阈值。带单位、空串、布尔值、指数或分隔符字符串均不自动猜测或修正。该类型转换由替身测试验证，以上真实请求未出现数字字符串，不能将其写成真实接口已复现的问题。

本轮新增 11 项解析测试，覆盖空条件、未支持指标、类型转换、分项诊断、失败追踪、结构与数量边界、冲突保留、明确条件保护和异常信息脱敏。真实验证只记录脱敏结果及请求 ID，不提交授权原文或密钥。

本轮界面复核还发现，模型会把“没有提供指标”的补充提示混入未支持要求；将系统提示词调整为缺少指标写入assumptions，unresolved仅保留实际不支持的要求。真实银行行业重试进入澄清状态，补充手动条件后可继续筛选；详细界面记录见UI-VALIDATION.md。用户随后要求停止继续验证，未再发起验证请求。
